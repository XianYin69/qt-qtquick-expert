# 问题解析

把用户诉求拆成可判定的四元组：版本口径、技术栈分支、输入物、验收标准。

## 动作

1. 确认 **Qt 版本口径**：Qt 6（默认）还是 Qt 5.15 遗留；未说明即按 Qt6 答并显式标注假设。
2. 确认 **技术栈分支**：C++ Widgets / Qt Quick(QML) / C++ 后端 + QML 前端 / PyQt / PySide。
3. 确认 **输入物**：代码片段、报错文本、构建日志、CMakeLists、`.qml` 目录、还是纯设计咨询。
4. 确认 **验收标准**：要「能不能这样写」「为什么崩」「怎么改」还是「怎么测」。
5. 信息不足且影响判据（如版本、平台、静态/动态链接）→ 问用户，一次一问；
   不影响判据则按合理假设继续并在「边界」段声明。

## 产出

- 一句问题定义 + 版本/栈/输入/验收四元组，写入逻辑链首节点。

## 兜底

- 用户只给截图式结论无代码：降级为「判据 + 取证命令」形式回答，不断言具体缺陷。
- 版本无法确定：两条口径都给，并标明分叉点（如 `QRegExp`、高 DPI 属性）。
