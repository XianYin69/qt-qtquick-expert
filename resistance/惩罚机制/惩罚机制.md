# 惩罚机制（熔断）

规定重试上限与超限动作，防止无进展空转。

## 规则

1. 重试计数按**错误签名**累计：同一节点、同一错误类型算同类。
2. 达 **10 次**即熔断，禁止继续原样重试。
3. 熔断动作（按序取其一）：
   - 回退当前功能分支（`git reset` 到上一稳定提交或弃分支）；
   - 降级为静态判据并标 `[本地]`（见 [降级策略](../降级策略/降级策略.md)）；
   - 求助用户，附根因分析（错误签名、已试次数、是否同类重复）。
4. 每次重试前必须先做根因分析并**换做法**（换参数/换探针/换叶/拆步），
   未分析即原样重试本身即违规。
5. 熔断事件记入过程链与错误链，供后续同类任务规避。

## 计数口径

| 情形 | 是否计数 |
|---|---|
| 同一探针同一错误重复失败 | 计数 |
| 换参数/换路径后失败 | 计数（但视为已修复尝试） |
| 用户补充信息后重跑 | 不计数 |
| 网络瞬时错误重试 | 计数，但上限前须先换源 |

## 违规后果

- 不熔断：预算耗尽、任务卡死，且掩盖真实根因；
- 未分析即重试：重复消耗且无新证据。
