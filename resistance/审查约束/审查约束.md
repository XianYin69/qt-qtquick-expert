# 审查约束（整体审查标准）

九项标准全部通过才算完成；任一项失败记过程链中断后回上游修复。

## 九项标准

| # | 标准 | 校验方式 |
|---|---|---|
| 1 | 悬空链接为 0 | `python -B scripts/check_links.py --root .` |
| 2 | 所有 `.md` ≤ 50 行 | 行数统计（脚本 `.py` 不限行数） |
| 3 | 脚本无 >100 字符行、无裸 `except`、无调试残留 | 逐行长度与模式检查 |
| 4 | 知识树九叶完整：叶 ↔ `knowledge/` ↔ `checklists/` 一一对应 | `knowledge_index.py` |
| 5 | `deps.json` 每条附 `source_url` 且字段齐全 | `knowledge_index.py --check-deps` |
| 6 | `SKILL.md` 含 YAML frontmatter，提示词一句话精简 | 读文件头与 `agent/` |
| 7 | `resistance/` 约束齐备且未被删改 | 目录比对 |
| 8 | 正反双链辩论已跑并记入逻辑链 | 辩论记录存在 |
| 9 | git：功能分支→dev→main 本地提交，未擅自推送 | `git log --oneline --all` |

## 交付级标准（顾问路径每次输出）

- 五段齐全：结论 / 依据 / 取证 / 边界 / 未覆盖（缺段即不合格）。
- 「已验证」字样必须对应真实运行输出；否则改标 `[本地]`。
- 分级不得升格：偏好只能 minor。

## 违规后果

- 跳过审查：陈旧或错误判据进入本体，后续所有回答继承该错误；
- 辩论缺失：单侧结论未经修正路径，高危判断（许可/ABI）风险不可见。
