# 垃圾回收机制

规定过程工件的存放、释放与删除，保证 skill 目录始终干净。

## 规则

1. 所有生成文件先落 `tmp/` 镜像（工作区 tmp 或 `SMS_TMP`），**禁止直写 skill 目录**。
2. 释放时机：审查通过后按 [update 接口](../../update/update.md) 的 compare → release 执行。
3. 释放后删除 `tmp/` 过程工件；未释放的变更不得留在本体。
4. 缓存文件（网页正文、下载物、`.pyc`、构建产物）**不得写入 skill 目录**，一律落用户缓存目录。
5. `.gitignore` 必须含 `tmp/`、`__pycache__/`、`*.pyc`、IDE 目录；暂存前核对 `git status`。
6. 未指定目标目录时按 [沙盒机制](../沙盒机制/沙盒机制.md) 在固定路径作业，交付后删除沙盒。

## 回收清单（收尾必查）

- `tmp/` 是否为空或已删除；
- 是否残留 `*.log`、`build/`、`moc_*.cpp`、`qrc_*.cpp`（本技能 `.gitignore` 已列）；
- 探针输出是否被误当成本体文件保存。

## 违规后果

- 缓存入库：技能体积膨胀、SMS 安装净化失败、隐私工件外泄；
- 未释放变更：本体与镜像分叉，下次修改基于陈旧内容。

## 兜底

- 删除失败（占用）：记过程链中断并报告路径，不得静默跳过。
