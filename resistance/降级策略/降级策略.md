# 降级策略

规定取证工具缺失、网络不可用、信息不足时的降级路径与标注义务。

## 降级矩阵

| 受阻情形 | 降级动作 | 标注义务 |
|---|---|---|
| 无 Qt 工具链（qmake/qmllint/windeployqt 缺失） | 只做静态判据，给用户可执行命令 | 全部结论标 `[本地]`，不得写「已验证」 |
| 无编译器/CMake | 不断言构建结果与性能差异 | 给可复现命令 + 前提假设 |
| 官方页不可达 | 用既有常识判据 | 标 `[本地]`，**禁止附 URL** |
| 用户未给版本 | 按 Qt 6 主口径答，并列 Qt 5.15 分叉点 | 「边界」段写明假设 |
| 用户未给平台 | 桌面优先，另注 Android/iOS 差异 | 「边界」段写明假设 |
| 无实测帧数据 | 只给场景图写法层面的疑点 | 不得断言「更快」，须给 Profiler 步骤 |
| 许可问题无原文 | 只指出风险点与需核对的页面 | 不得替用户作合规结论 |

## 规则

1. 降级不等于放弃：必须同时给出**用户可自行取证**的命令或页面名。
2. 降级项一律进「未覆盖」段，不得混进「依据」段。
3. 降级后仍要满足交付五段齐全（结论/依据/取证/边界/未覆盖）。
4. 连续降级达 10 次同类错误：触发 [惩罚机制](../惩罚机制/惩罚机制.md) 熔断。

## 违规后果

- 降级却写「已验证」：伪造取证，用户据以部署后失败，不可追溯；
- 未给替代命令：任务实质停滞，等于空手拒绝。
